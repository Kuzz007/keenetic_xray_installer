# Каналы обновления агента

Безопасное обновление `xray-go-agent` использует два канала и два локальных
слота. Этот механизм обновляет только агент. Router bundles Full/Minimal
публикуются рядом с ним, но не заменяют A/B-контракт работающего агента.

## Каналы

- `latest` — стабильный GitHub Release. Manifest создаётся при обычном
  release-please/GoReleaser релизе и публикуется в mutable release `latest`.
- `dev` — автоматический prerelease из актуального commit `main`. Он создаётся
  workflow `dev-release.yml` только после прохождения `go test ./...`. Этот же
  prerelease содержит dev control-server для VPS и оба router bundle.

Агент не исполняет файлы из raw-веток. Сначала он скачивает
`agent-channel.json`, проверяет schema, channel, архитектуру, имя asset, размер
и SHA256. После загрузки бинарник ещё раз проверяется по SHA256 и запускается с
`-version` до изменения активной версии.

Подтверждение установки привязано к version и SHA256 из показанного
предпросмотра. Если mutable-канал успел измениться между проверкой и нажатием
кнопки установки, агент остановится и попросит заново проверить канал.

## Меню Telegram

Новый агент сообщает capability `agent_release_update`. После этого старая
кнопка прямого обновления заменяется кнопкой `🤖 Агент`.

Порядок работы:

1. Выбрать `Latest` или `Dev`.
2. Дождаться предпросмотра версии, commit и размера.
3. Отдельно подтвердить установку.
4. Дождаться перезапуска агента и результата проверки связи.

Все состояния отображаются редактированием одного сообщения. Кнопка `Откат`
переключает агент на второй локальный слот без скачивания из интернета.

## A/B и автоматический откат

При первом безопасном обновлении текущий рабочий агент копируется в slot A.
Новая версия загружается в slot B. При следующих обновлениях используется
неактивный слот.

После переключения новая версия обязана:

1. успешно запуститься;
2. загрузить существующую конфигурацию агента;
3. подтвердить связь с control-server через `agent_start`;
4. записать health marker текущей транзакции.

Если marker не появился примерно за 90 секунд, внешний runner возвращает
предыдущий слот и перезапускает сервис. Boot helper с номером `S27` выполняет
тот же консервативный откат, если роутер перезагрузился в середине транзакции.

Состояние хранится без токенов и VPN-источников:

```text
/opt/etc/xray/agent-update-state.json
/opt/libexec/xray-go-agent-update/slots/a/xray-go-agent
/opt/libexec/xray-go-agent-update/slots/b/xray-go-agent
/opt/var/run/xray-go-agent-update.pending
/opt/var/log/xray-go-agent-release-update.log
```

## Первый переход

Существующий старый агент ещё не знает capability `agent_release_update`.
Для него кнопка `🤖 Агент` показывает одноразовый bootstrap `Latest`/`Dev` и
готовую команду для копирования на роутер. Это единственный прямой переход без
A/B: старая версия физически не умеет создавать слоты. После следующего
heartbeat control-server автоматически переключает ту же кнопку на безопасное
меню каналов, а текущий рабочий бинарник становится первым A/B-слотом.

Для теста меню до стабильного релиза control-server на VPS обновляется из того
же канала:

```sh
curl -fsSL https://raw.githubusercontent.com/Kuzz007/keenetic_xray_installer/main/scripts/xray-go-control-server-install.sh \
  | TAG=dev sh -s -- --update-only --yes
```

Если dev control-server не установлен на VPS, живой Telegram-бот продолжит
показывать интерфейс своей старой версии, даже когда dev assets уже появились
на GitHub.

В новой версии совместимая команда `update_agent`, включая массовую команду
старого интерфейса, также направляется в безопасный A/B updater канала
`latest`; прежний запуск скачанного raw shell installer больше не используется.
